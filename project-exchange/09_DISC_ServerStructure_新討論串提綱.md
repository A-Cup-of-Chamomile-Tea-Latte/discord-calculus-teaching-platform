# Discord 伺服器設定、身份與權限結構
## 新討論串提綱

本討論串只處理「學生實際看到什麼、誰能做什麼、伺服器如何排列」；不處理 Codex 程式審核、打包錯誤或 Google Sheets 實作細節。

---

## 一、目前已確認的整體原則

### 1. NTU COOL

NTU COOL 仍是正式課務平台，負責教材、作業、成績、正式公告與課程政策。Discord 與入口網站只作補充。

### 2. Discord

Discord 是主要討論空間，學生可直接發文。入口網站代為發文只是替代方式，不是主要或唯一入口。

### 3. 學生直接在 Discord 發文時，機器人不代替發文

學生本人建立文章，機器人負責整理格式與狀態：

1. 學生輸入標題與內容。
2. 透過 Discord 選單或表單選擇文章屬性。
3. 機器人檢查選項。
4. 機器人替原文章加入標題前綴、後綴或 Forum 標籤。
5. 原文作者仍是學生本人。

例如：

```text
原標題：
Chain rule 的問題

整理後：
[C12][觀念][AI✓] Chain rule 的問題
```

可選屬性可能包括：

- 班級
- 問題類型
- 是否允許 AI 輔助教學分析
- 可見範圍
- 目前狀態

### 4. 網站代為發文時

學生在網站填寫同一套屬性，由課程助理機器人代為建立 Discord 文章。網站與 Discord 兩種入口應共用相同的案件欄位、標籤與狀態規則。

### 5. 資料整理機器人

`dump_bot` 負責：

- 指定討論串匯出
- 案件摘要更新
- 舊伺服器結構盤點
- 每週資料整理
- 唯讀檢查

它不負責修改學生身份組或建立正式伺服器結構。

# 二、核心討論問題

## A. 使用者身份

預計身份：

- Professor
- TA
- Verified Student
- Class Member
- Approved Guest
- System Administrator
- Bot

需要決定：

1. 哪些身份需要 Discord 身份組？
2. 哪些只存在資料庫？
3. 哪些身份會公開顯示？
4. 教授與助教是否必須分開？
5. 系統管理員是否等同助教？
6. 特許加入者能看到哪些區域？

---

## B. 班級與顯示名稱

目前學生暱稱格式：

```text
nnmmm
```

- `nn`：班級
- `mmm`：該班加入順序

需要決定：

1. 是否所有學生預設使用 `nnmmm`？
2. 是否允許改成真名？
3. 教授與助教能否查到代號與真實身份的對照？
4. 什麼情況允許完全匿名？
5. 匿名發文後，後續回覆是否只能透過機器人表單？
6. 非標準班級是否統一使用 `C99`？
7. 班級應做成身份組、文章標籤，還是只存在資料庫？

---

## C. 伺服器主要區域

候選區域：

```text
START HERE
QUESTIONS
COMMUNITY
PRIVATE SUPPORT
VOICE
TEACHING STAFF
SYSTEM
ARCHIVE
```

需要決定：

1. 第一版哪些一定要有？
2. 哪些可以延後？
3. 是否需要助教內部區？
4. 是否需要學生可見的系統狀態區？
5. 舊文章留在原區、封存區，還是只用 Discord 自動封存？

---

## D. 課程提問區

### 方案一：全課程共用一個 Forum

優點：

- 問題較不易重複。
- 助教資源集中。
- 學生可看到其他班的有用回答。

需要處理：

- 如何標示班級？
- 是否允許所有學生互相回覆？
- 不同教授的教學進度是否會衝突？

### 方案二：每班一個 Forum

優點：

- 結構與權限直觀。
- 行政與進度差異容易管理。

缺點：

- 問題容易重複。
- 頻道數量較多。
- 助教跨班回答較麻煩。

### 方案三：全課程 Forum 加班級標籤

需要確認 Forum 標籤數量是否足夠，以及班級標籤是否占用太多位置。

---

## E. 學生直接發文流程

建議流程：

```text
學生建立文章
→ 輸入標題與內容
→ 選擇文章屬性
→ 機器人驗證
→ 機器人整理標題與標籤
→ 建立案件編號
→ 進入待回答狀態
```

需要決定：

1. 學生可先發文再整理，還是必須先完成選單？
2. 機器人可以修改標題到什麼程度？
3. 學生之後能否自行改標題？
4. 問題類型有哪些？
5. AI 分析選項放在標題、標籤，還是兩者都有？
6. 班級代碼是否放在標題？
7. 案件編號放在標題尾端，還是放在第一則機器人訊息？

---

## F. 文章狀態

候選狀態：

- Open
- Answered
- Waiting for Student
- Escalated
- Temporarily Closed
- Closed

需要決定：

1. 哪些由機器人自動設定？
2. 哪些只能由助教或教師設定？
3. 學生能否按「已解決」？
4. 重新開啟後回到 Open，還是保留 Reopened？
5. Reopened 是長期狀態，還是時間軸事件？
6. Discord 自動封存與案件結案如何配合？

---

## G. AI 輔助教學分析

發文時使用二選一：

```text
是否允許 AI 輔助教學分析？
○ Yes
○ No
```

需要決定：

1. 原發文者選 No 時，是否整案排除？
2. 原發文者選 Yes 時，其他學生的回覆如何處理？
3. 助教與教師的回覆是否預設允許？
4. Discord 標題是否使用 `AI✓／AI×`？
5. 是否同時使用 Forum 標籤？
6. 學生之後能否修改選擇？
7. 修改後，既有匯出資料如何處理？

---

## H. Private Support

目前傾向使用 private thread，但仍需討論：

1. 學生如何建立？
   - Discord 按鈕
   - Discord 表單
   - 入口網站
2. 哪些人預設可見？
3. 教授是否一開始就可見？
4. 學生是否可指定助教？
5. 是否允許附件？
6. 是否有私人案號？
7. 是否顯示在網站的「我的案件」？
8. 誰可以結案？
9. 關閉後能否重新開啟？
10. `dump_bot` 是否完全禁止讀取 Private Support？

---

## I. 一般聊天與資源分享

需要決定：

1. 是否開放一般聊天區？
2. 是否另設資源分享區？
3. 是否允許學生貼外部連結？
4. 是否需要慢速模式？
5. 是否允許學生建立一般討論串？
6. 一般聊天內容是否納入教學分析？
7. 是否允許學生私訊助教？
8. 使用指南是否建議關閉共同伺服器成員的直接私訊？

---

## J. 語音區

候選：

- Office Hours
- Study Room
- Temporary Help Room

固定原則：

- 不錄音
- 不自動轉錄

需要決定：

1. 第一版是否建立語音區？
2. 誰能開啟或主持？
3. 是否保留語音區附屬文字聊天？
4. 附屬文字聊天是否納入案件或分析？
5. 是否需要預約制度？

---

## K. 機器人權限

### 課程助理機器人

可能需要：

- 查看頻道
- 發送訊息
- 在討論串發送訊息
- 建立公開討論串
- 建立私人討論串
- 管理討論串
- 讀取歷史訊息
- 使用應用程式指令
- 管理暱稱
- 管理身份組

需要決定：

1. 是否真的需要管理身份組？
2. 是否需要管理頻道？
3. 是否需要建立私人討論串？
4. 是否需要讀取成員列表？
5. 是否需要特殊成員事件權限？

### 資料整理機器人

預計只需要：

- 查看指定頻道
- 讀取歷史訊息
- 使用應用程式指令
- 發送匯出結果
- 附加檔案

固定原則：

- 不給 Administrator
- 不給 Manage Roles
- 不給 Manage Channels
- 舊伺服器盤點以唯讀為主

# 三、舊 112／113／114 伺服器盤點

這項工作可與新伺服器設定討論平行進行，也可以同時測試 `dump_bot` 的真實唯讀能力。

## 第一階段：只抓結構

目標：

- 比較三年伺服器設計。
- 找出值得沿用或避免的結構。
- 測試 `dump_bot`。
- 不讀取對話正文。

預計抓取：

- Server 基本資料
- Category 結構
- Channel 類型與順序
- Forum 與標籤
- Roles
- 權限覆寫
- Bot 清單
- Active／Archived thread 數量
- Auto-archive 設定
- Slow mode
- Channel topic

輸出：

```text
112-server-structure.json
113-server-structure.json
114-server-structure.json
server-structure-comparison.md
```

## 第二階段：活動摘要

需另行核准：

- 每月訊息量
- 活躍討論串數
- 未回覆文章數
- 回覆時間
- 教師／助教／學生角色分布
- 尖峰時段

可以先不讀訊息正文，只使用必要統計或 metadata。

## 第三階段：去識別化對話樣本

需再次核准：

- 移除姓名、學號、Discord ID、頭像與附件資訊
- 保留角色、時間、回覆關係與文章類型
- 產生測試資料
- 提供教學互動與語氣分析
