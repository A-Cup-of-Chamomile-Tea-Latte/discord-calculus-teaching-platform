# Discord Calculus Teaching Support Platform

## 文件狀態

本章程是 115-1 微積分模組教學支援原型的工作草案，用來對齊教授、助教與開發協作者。它不代表臺大、授課單位或任何行政機構已核准本系統。

## 我們要解決的問題

學生常在「問題還不夠完整」、「不知道該在哪裡問」或「不想公開身分」時延後提問；助教則可能在 Discord、個別 email 與口頭詢問之間重複回答相近問題，也不容易追蹤案件是否已回應。現有流程留下的紀錄格式不一致，後續想檢視常見學習困難時，往往需要人工複製整段對話。

本專案希望加上一層輕量、可選擇且可追蹤的教學支援，不改變正式課務平台的權威性。

## 目標

- 降低學生提出問題的心理與操作門檻，保留直接在 Discord 發問與由網站代送兩條路徑。
- 讓一般問題有可讀的案件編號、明確狀態與按需查詢入口。
- 讓助教較少重複處理一對一詢問，並能辨認尚待回覆或需升級處理的問題。
- 清楚區分作者顯示方式、內容可見範圍與教學分析同意，讓使用者理解各選項的限制。
- 以可重現的 JSON/Markdown 匯出取代臨時複製對話，為日後人工檢視教學品質提供較乾淨的材料。
- 先用虛構資料與可逆原型驗證流程，再決定是否接入正式服務。

## 非目標

- 不取代 NTU COOL，也不在 Discord 或入口網站發布成績、正式期限或課程政策的唯一版本。
- 不監控所有對話、不持續輪詢所有案件、不錄製或自動轉錄語音。
- 不自動替學生評分、不建立學生風險分數、不把對話直接用於模型訓練。
- 不以 Discord OAuth2 或伺服器暱稱單獨證明臺大課程身分。
- 不把 Google Sheets 當成高頻訊息資料庫，也不逐則同步所有 Discord 訊息。
- 第一版不承諾正式服務等級、機構核准或全自動教學分析。

## 利害關係人

- **學生**：需要容易理解、可選擇公開程度且能追蹤回覆的提問管道。
- **助教**：回覆一般問題、處理需保護的求助、維護案件狀態並進行明確啟動的匯出。
- **授課教師與課程管理者**：界定課程政策、監督隱私與教學用途、檢視原型是否真正減少摩擦。
- **系統維護者**：維持入口網站、bots、Apps Script 與本機工具的安全邊界。
- **隱私／研究倫理相關審查者**：若未來要正式分析或研究使用，確認告知、同意、保留與刪除規則。

## 第一版範圍

1. 繁體中文靜態入口網站的資訊架構、隱私引導與系統狀態。
2. 一般案件的網站代送表單、可設定案件編號與單筆按需查詢原型。
3. 與 Discord forum post/thread 的映射，以及由 bot 代貼的匿名回覆概念驗證。
4. 與一般案件分離、只有授權教職員可見的 Private Support 流程骨架。
5. email 驗證、Discord account 綁定及單次、限時、可稽核 activation code 的本機／mock 流程。
6. 以 Google Sheets / Apps Script 作原型管理層的本機程式與 schema，不建立雲端專案。
7. 管理者明確啟動的 Discord thread 匯出、同意判定、匿名化與批次匯入工具。
8. 共用資料契約、虛構 fixtures、測試、安全與操作文件。

## 平台責任

| 平台 | 負責 | 不負責 |
|---|---|---|
| NTU COOL | 教材、作業、成績、期限、正式公告與政策 | 社群式即時討論工具 |
| Discord | 提問、討論、助教回覆、資源整合、選用語音 office hour | 正式課務唯一來源；第一版不錄音／轉錄 |
| 入口網站 | onboarding、隱私指引、可選的代送問題、一般案件查詢、Private Support 入口、設定與狀態 | 直接持有 bot token；公開查詢 Private Support |
| Sheets / Apps Script | 原型資料與行政管理介面 | 高頻訊息資料庫、逐訊息即時同步 |
| 本機工具 | 明確啟動的匯出、匿名化、報告準備與批次匯入 | 常駐監控、自動送往 AI |

## 成功訊號

第一階段不先宣稱改善幅度，而以可觀察訊號判斷原型是否值得繼續：

- 學生能在不需理解技術架構的情況下選擇直接 Discord 或網站代送，並知道誰看得到內容。
- 使用有效案件編號能取得一般案件狀態；Private Support 無法由公開查詢取得。
- 匿名提問／回覆不需要先以個人 Discord 身分公開再刪除。
- 助教能從狀態與案件紀錄辨認下一步，減少反覆搜尋或複製貼上。
- 同一份 fixtures 能被 Portal、GAS、bots 與本機工具驗證。
- 匯出結果保留回覆關係、編輯、附件 metadata、時間與同意資訊，且 Private Support 預設排除。
- 使用者測試與助教回饋顯示流程比現況更清楚；正式量化指標須在試用設計與隱私審查後另行決定。

## 工作原則

- 隱私預設、最小權限、fixture-first、可逆變更。
- 不把「匿名顯示」誤稱為對管理者也不可識別。
- 網站代送是替代路徑，不是學生必經流程。
- 教學分析只在管理者明確匯出、依同意處理後進行；不是即時監控。
- 未定事項須標示並記錄，不以實作細節偷偷決定產品政策。
