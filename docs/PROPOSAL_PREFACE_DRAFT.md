# Discord Calculus Teaching Support Platform

## 微積分模組教學支援優化提案：執行摘要與前言草案

## 文件狀態

本文件是供授課教師、助教與後續審查者討論的草案。它不代表臺大、授課單位或任何行政機構已核准系統，也不宣稱已完成正式 Discord、Google 或 email 整合。

## 執行摘要

微積分課程中，學生常在問題尚未完整、不確定該在哪裡發問，或擔心公開身分時延後求助。助教則可能在 Discord、email 與口頭詢問之間重複回覆，且缺乏一致的追蹤與後續檢視紀錄。

本提案建議以 **NTU COOL 為正式課務來源**，Discord 補充提問、討論與助教互動，再以一個輕量 Portal 提供 onboarding、隱私引導、可選的網站代送、一般案件按需查詢與獨立 Private Support 入口。它不取代 NTU COOL，不要求所有學生都經過網站發問，也不持續監看所有 Discord 對話。

第一階段已以 Astro static Portal、版本化資料契約、虛構 fixtures、mock adapters 與本機 Python 工具建立可測試的原型。管理者可以對一個明確選定的虛構 thread 產生 JSON/Markdown，再套用 consent filter、去識別化、人工複核與 batch-import dry run。這些成果驗證了流程與邊界，不等於已有 production service、機構授權或不可逆匿名保證。

建議下一階段不立即全面上線，而是先用可抽離的 fixture demo 與小規模可用性討論，檢查學生是否能理解三種隱私維度、助教是否能降低重複整理、Private Support 是否真正隔離，並在正式試用前完成身分驗證、權限、保留／刪除、同意撤回、abuse controls、事故應變與 GitHub Pages 公開範圍的決策。

## 提案前言

微積分課程中的提問不只發生在學生已經能把疑惑整理成完整題目的時刻。更多時候，學生可能只是察覺某一步推導跟不上、不確定自己的問題是否「值得問」，或擔心在同學面前暴露基礎不足。當正式課務平台、Discord 討論、個別 email 與口頭詢問並存時，學生也可能不知道哪一條路徑最合適，因而延後甚至放棄求助。

對教學團隊而言，分散的提問同樣造成負擔。助教可能在不同管道重複回答相近問題，難以確認某一項求助是否已有後續，也不容易把一段討論完整整理成可回顧的教學紀錄。若要在學期後檢視學生常見的卡點，目前常見做法仍是人工複製對話、重新整理作者與時間，費力之餘也容易忽略隱私與同意的界線。

本提案希望探索一個輕量的教學支援層：以 NTU COOL 繼續承擔教材、作業、成績、期限、正式公告與課程政策的權威角色；Discord 則補充提問、討論、資源整合與助教互動。另設一個簡潔入口網站，提供 onboarding 與隱私說明，也讓不想開啟 Discord 發文的學生可選擇由網站代送問題。網站代送不是必經流程，學生仍可直接在 Discord 發問。

一般問題可建立人可閱讀的案件編號，讓學生按需查看處理進度；較敏感的求助則由獨立 Private Support 路徑處理，不進入公開案件查詢。作者顯示方式、內容可見範圍與教學分析同意會被分開說明，避免把「暱稱」、「匿名」或「只給教學團隊看」混成同一件事。特別是 Discord 伺服器暱稱無法遮蔽全域帳號資料，完全匿名的內容也不能採取「先以本人發文、再立即刪除」的做法。

這個原型的重點不是用新技術取代既有課務系統，也不是即時監控學生。第一版不錄音、不自動轉錄語音、不持續抓取全部對話、不替學生評分。Google Sheets 與 Apps Script 僅作原型及行政管理工具，不承擔高頻訊息資料庫的角色。Discord 對話只有在管理者明確選取 thread 並啟動匯出時，才轉成保留時間、回覆關係、編輯、附件 metadata 與同意資訊的 JSON/Markdown 紀錄。

未來若要使用 AI 協助教學品質檢視，也應建立在明確匯出、同意判定、去識別化與人工複核之後，由授權人員延後啟動。它不應變成對學生的隱性監視、模型訓練預設或自動能力判定。Private Support 預設排除於此用途，一般討論亦應提供清楚的帳號預設與逐篇調整方式。

因此，第一階段先以完全虛構的 fixtures 與 mock adapters 驗證：學生是否看得懂提問選項與隱私差異、助教是否能用案件狀態減少重複整理、一般案件與 Private Support 是否確實隔離，以及同一份資料契約能否被 Portal、管理工具、bots 與本機匯出流程共同使用。只有在流程、權限、配額、風險與事故應變經過實測後，才討論正式服務連接與試用。

本草案尚未獲得機構核准，也不預設特定成效。一般案件 prefix、資料保留／刪除期限、分析告知與撤回文字、正式 Discord 權限、Apps Script 配額、public case lookup 保護與 Pages access scope 仍待決定。後續評估應以學生與助教的實際使用回饋為主，判斷這套支援層是否真的降低提問門檻與重複工作，而不是只增加另一套需要維護的工具。
